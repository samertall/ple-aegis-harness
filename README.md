## What is implemented

- WebSocket protocol v1 server (`serve.py` and `protocol.py`), including `exec`, `read_file`, `write_file`, authorized `http`/MCP relay, usage, cancellation, and `done` messages.
- Agent loop (`harness.py`) using evaluator-injected **Gemini 3.8 Flash** via the OpenAI-compatible endpoint; instruction-grounded exploration, file creation, source audits, model retry handling, safe context shortening, and a verification gate after apparent completion.
- Structured MCP Streamable-HTTP initialization, tool discovery, and tool calls (`mcp_bridge.py`). The MCP server names/URLs come only from the current task.
- Configurable ablations: `VERIFY_GATE`, `ENABLE_INVENTORY`, `MAX_AGENT_TURNS`, `MAX_COMPLETION_TOKENS`.
- Automated mocked tests, including an actual local WebSocket evaluator simulation.
- Architecture, cover, and **explicitly unscored** placeholder score/failure visuals; regenerable scripts for real metrics.

No benchmark scores, licensed-engineer approval, or competition validation are claimed.

## Reproduce official validation (WSL2 / Linux recommended)

Install `git`, `uv`, Docker Desktop with WSL2 integration, and Harbor. Accept gated dataset terms through the Hugging Face site and set a read-only HF token.

Use two sibling repositories:

```bash
# Repo containing the official kit
git clone https://github.com/google-research/ple.git
# In a second terminal clone YOUR PUBLIC REPO for this harness beside 'ple'.
# Example: git clone https://github.com/<your-user>/ple-aegis-harness.git

uv tool install harbor==0.20.0 --with websockets
cd ple
export HF_TOKEN='YOUR_HUGGINGFACE_READ_TOKEN'
# Choose your own authorized model gateway to run local dev tasks:
export MODEL_PROXY_URL='http://localhost:4000'
export MODEL_PROXY_KEY='YOUR_LOCAL_PROXY_KEY'

uv run python -m kit check ../ple-aegis-harness
uv run python eval/run.py ../ple-aegis-harness
uv run python -m kit artifacts ../ple-aegis-harness
```

For the selected `google-cloud/gemini-3.8-flash` model, the [free-only route](docs/FREE_GEMINI_RUNBOOK.md) uses the same Gemini 3.8 Flash model from Google AI Studio Free Tier, accessed through a local LiteLLM proxy. Use an unbilled AI Studio project only; do not activate Vertex AI billing. Availability is subject to the account's actual free-tier quota. Sponsored Stage 2 evaluation supplies a model key without your billing account; local development does not.

When the official run finishes, `artifacts/` is generated by the kit, not manually. Inspect `results.json`, per-task outputs, and model usage. Build real, repeatable metrics using `metrics/dev_runs.csv` and `metrics/failures.csv`; run `python figures/build_figures.py` again. Do not use current empty-data placeholders in a submitted Writeup.

If the official kit reports missing artifacts before the first run, follow the kit's documented order for smoke validation and dev-set generation. Do not claim passing either check until verified.

## Ablation matrix

For each model used in a dev run, hold task set, model, prompts, output directory and evaluation settings fixed and change **only one** harness parameter:

| Configuration | Environment |
|---|---|
| baseline | `VERIFY_GATE=0 ENABLE_INVENTORY=0` |
| evidence inventory only | `VERIFY_GATE=0 ENABLE_INVENTORY=1` |
| full Aegis | `VERIFY_GATE=1 ENABLE_INVENTORY=1` |
| reduced budget | same full Aegis settings + `MAX_AGENT_TURNS=50` |

Run at least two genuinely available models, e.g. the nominated Claude and a Gemini family model, via authorized local development endpoints; restore `submission.yaml` to exactly one `google-cloud/<id>` before the final commit. Compare 29-task scores, cost/tokens, task-specific failures and the effect of each ablation. ## Submission procedure

1. Finish model-backed validation and fix any official kit issues.
2. Run all 29 public dev tasks with authorized benchmark and model access.
3. Produce truthful metrics, analyze errors and regenerate figures 02/03.
4. Commit `artifacts/` alongside the harness in your GitHub repo, ensuring the full root directory passes artifact size/file count rules.
5. Obtain 40-character SHA with `git rev-parse HEAD`, push to GitHub, and verify it online.
6. In Kaggle open **Writeups → New Writeup**. Paste the completed under-2,000-word draft, attach cover and three real figures, add the GitHub repo under **Project Links**, put the 40-char commit SHA at the top, and click **Submit**.

Kaggle Drafts are not judged. Never publish keys or tokens. Do not use Git LFS/symlinks for artifacts.
